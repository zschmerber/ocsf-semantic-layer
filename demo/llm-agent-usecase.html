💡 The Problem

Traditional security data lakes require analysts to:

  • Know complex OCSF schema structure (nested JSON paths)
  • Understand field mappings (query.hostname, src_endpoint.ip)
  • Write complex SQL with nested field access
  • Manually correlate with MITRE ATT&CK techniques

The semantic layer + LLM context solves this by providing AI agents with:

  • Business-friendly attribute names and synonyms
  • Security context for each field
  • MITRE ATT&CK technique mappings
  • Pre-built query templates for common threats
  • Sample values and patterns

💾 Generated SQL Query
-- DNS Tunneling Detection (MITRE T1048.003) SELECT query_hostname, query_type, source_ip, COUNT(*) as query_count, COUNT(DISTINCT query_hostname) as unique_domains FROM v_dns_event WHERE query_type IN ('TXT', 'NULL') AND event_time >= CURRENT_TIMESTAMP - INTERVAL 24 HOURS GROUP BY source_ip, query_type HAVING query_count > 10 -- Unusual volume ORDER BY query_count DESC;

MITRE ATT&CK Context:

T1048.003 Exfiltration Over Alternative Protocol: Exfiltration Over Unencrypted/Obfuscated Non-C2 Protocol

Adversaries may steal data by exfiltrating it over a different protocol than the main command and control channel. DNS tunneling encodes data in DNS queries/responses to bypass network security controls.

Recommended Actions:

  1. Isolate source IP 10.200.21.100 (highest risk)
  2. Analyze queried domains for data encoding patterns
  3. Check for corresponding C2 infrastructure
  4. Review firewall logs for related activity
  5. Implement DNS query length limits

📦 What's in the LLM Context?

File: demo/output/llm-context.json (19 KB, ~4,760 tokens)

The context includes everything an AI agent needs to understand and query the DNS semantic layer:

1. Entity Definitions

Complete DNS event entity with 10 attributes, each including:

  • Name and type
  • Description
  • Security context
  • Sample values
  • Dimension/observable flags

2. Synonyms (27 total)

Natural language mappings for each attribute:

  • query_hostname → domain, fqdn, hostname
  • source_ip → client_ip, src_ip
  • action → disposition, verdict

3. MITRE ATT&CK Mappings

Threat relevance for security attributes:

  • T1071.004 - DNS Protocol
  • T1568.002 - DGA
  • T1048.003 - DNS Tunneling

4. Query Templates (12)

Pre-built detection queries:

  • DGA detection
  • DNS tunneling
  • C2 beaconing
  • Threat intel matching

5. Computed Fields (4)

Threat detection logic:

  • is_suspicious_tld
  • is_dga_candidate
  • query_entropy
  • is_long_domain

6. Security Context

Why each field matters:

  • Threat detection use cases
  • Attack patterns to look for
  • Recommended analysis approaches
